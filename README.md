# AI Design Infrastructure

A structured, AI-assisted design process built on Claude Code. 30 executable skills, a four-tier pipeline, two cross-cutting compounding knowledge modes, and a sync loop that keeps canvas briefs, Figma screens, and coded prototypes in alignment.

> **v2.1** — cleanup release. Operational-model lens (Ingest / Query / Lint), batch ingest orchestrator, automatic migrations for wikilink format + BRD manifest consolidation + legacy-file cleanup. Existing projects receive all migrations automatically on `git pull` via `migrate.js`.
>
> **Upgrading from v1 or v2.0?** See [MIGRATION.md](MIGRATION.md) for step-by-step instructions.

---

## The big idea

Most AI-assisted design work is ad hoc. You ask, Claude answers, you figure out what to do with it. This repo inverts that. Claude is the executor. You are the design director. The process is the contract between you.

The pipeline flows through four tiers — plus two cross-cutting modes that work at any tier:

```
TIER 1: DISCOVERY    → Understand the problem and who has it
TIER 2: DEFINITION   → Structure what to build (tech and UI agnostic)
TIER 3: DESIGN       → Decide how it looks, feels, behaves, and reads
TIER 4: DEVELOP      → Build screens, prototype, and keep everything in sync

CROSS-CUTTING:       → design-lint (health check) + design-query (knowledge wiki)
```

Tier 4 is a sync loop between three nodes:

```
Canvas Brief ◄──sync──► Figma Screens ◄──sync──► Prototype
     ▲                                                │
     └────────────────── sync ────────────────────────┘
```

Each node owns different concerns. Changes propagate bidirectionally. Small changes auto-sync. Structural changes flag drift and require approval before propagating.

### Operational model — Ingest / Query / Lint

A cross-cutting lens over the 30 skills. Tier tells you *when* a skill runs; operation tells you *what kind of work* it does. Every process chapter carries an `operation:` YAML frontmatter field; the viewer exposes a `By Tier` / `By Operation` toggle.

- **INGEST** — turn raw inputs or upstream artifacts into authoritative artifacts. Most Tier 1–3 skills plus the Figma build pipeline.
- **QUERY** — aggregate the corpus into a retrieval surface. Canvas briefs (per-screen), WIKI (per-entity), docs pages, inventory.
- **LINT** — cross-check for drift, gaps, and principle violations. `design-lint`, `design-validation`, `figma-audit`, plus the three Phase-B synthesis passes.

Three Phase-B synthesis passes run in order: `design-research` → `design-governance` → `design-query`. Each consumes its predecessor's output.

## How it works

**Process chapters** (`design/process/`) are the single source of truth. 18 numbered markdown files define each design mode: its mental model, process steps, outputs, rules, and downstream connections. You never edit these directly; you tell Claude what to change and it propagates updates to all affected skill files and `CLAUDE.md`.

**Skills** (`.claude/skills/`) are the executable layer. Each skill corresponds to a design mode and contains a `SKILL.md` that Claude reads as a workflow specification when invoked. 30 skills total: one per design mode plus 11 specialized Figma pipeline skills.

**Artifact versioning** keeps the pipeline honest. Every output file carries a version header. Every mode directory contains `_upstream.md`, a manifest tracking which upstream artifacts were consumed and at which versions. When upstream changes, the affected mode reports staleness on next invocation and asks whether to re-process.

**The compounding knowledge loop** (v2) closes the gap between generating artifacts and querying them. `design-query` synthesizes all tier artifacts into a cross-referenced wiki and answers natural-language questions about the project — filing insights back as the corpus grows richer with each query.

## Getting started

### Requirements

- [Claude Code](https://claude.ai/code) (CLI)
- Figma desktop app + the Figma Console plugin (for Tier 4 only)
- Node.js v18+ (for sync scripts and process viewer)

### Setup

```bash
git clone <repo-url>
cd ai-design-infrastructure
```

Open the project in Claude Code:

```bash
claude
```

Claude will load `CLAUDE.md` automatically. From there, invoke any skill by describing what you want to do. Claude matches the intent to the right skill and executes the workflow.

### (Optional) Install the post-merge hook

To automatically detect toolchain updates after every `git pull`:

```bash
cp design/scripts/post-merge-hook.sh .git/hooks/post-merge
chmod +x .git/hooks/post-merge
```

### Run the process viewer

A local reading interface for the design process documentation. Renders all 18 chapters with navigation, keyboard shortcuts, and live reload:

```bash
cd design/viewer
npm install
npm run dev
```

Opens at `http://localhost:5200`. Use `←` / `→` arrow keys to move between chapters. Toggle `By Tier` / `By Operation` in the sidebar to switch grouping.

### Batch ingest

For projects with a large backlog of raw inputs (interviews, research notes, transcripts, docs), use the batch orchestrator instead of calling each mode individually:

```bash
node design/scripts/ingest-batch.js <directory-or-file-list>
```

Runs `design-discovery` once over the batch, reports downstream staleness via `sync-status.js`, and offers a single-prompt re-run of affected modes in dependency order. Ends with a `design-lint` summary. Opt-in — skip it if you prefer per-mode human gates.

## Principles

**Journeys and stories are tech and UI agnostic.** Tiers 1 and 2 describe what users do and experience: no screen names, no button labels, no UI patterns. This keeps upstream thinking portable.

**Canvas briefs are the single source of truth for intent.** No Figma screen gets built without a canvas brief. No prototype screen without a Figma implementation. The brief says it, Figma builds it, the prototype implements it.

**Zero hardcoded values in Figma.** Every color, spacing, and radius references a variable. Audits fail on any hardcoded value found.

**Every design decision traces back.** To a persona, a story, or a design principle. If you can't trace it, question it.

**Staleness is visible.** Every mode checks upstream on entry, artifact versions are tracked, and post-change notifications list affected downstream modes. No mode silently operates on outdated inputs.

**The corpus compounds.** Every query makes the project knowledge richer. Gaps become AC notes. Contradictions surface to the lint queue. Patterns elevate to governance. The design system learns.
