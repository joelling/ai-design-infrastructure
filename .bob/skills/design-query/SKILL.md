# design-query — Wiki Bootstrap + Ongoing Query (Bob)

## Purpose

Compound the project's knowledge. Phase A one-shot builds a navigable cross-referenced wiki; ongoing Phase B answers questions and files the answers back so the corpus gets richer every cycle.

## Phase A — Wiki bootstrap (run once)

### Step 0 — Readiness check

Confirm Tier 3 artifacts have stabilized:

- `design/02_USER_MODELS/` contains personas with confidence labels.
- `design/04_PROCESS_FLOWS/business-rules-register.md` exists.
- `design/06_INFORMATION_ARCHITECTURE/` has sitemap + screen inventory.
- `design/07-09/` Tier 3 decision artifacts exist.
- `design/12_GOVERNANCE/` has at least initial principles.

If any is missing, warn and offer to run the relevant skill first.

### Step 1 — Generate entity pages

Read the full corpus. Produce `design/WIKI/`:

- `index.md` — entry point with link farms per category.
- `personas/{persona-id}.md` — one page per persona with confidence, evidence, JTBD links, story references, screen affinities.
- `principles/{GP-NNN}.md` — one per governance principle with source decision, examples, violations flagged by `figma-audit`.
- `constraints/business-rules/{BR-NN}.md` — one per rule with source document, story refs, interaction impact.
- `constraints/accessibility/{pattern}.md` — WCAG patterns keyed by component.
- `patterns/{PA-NNN}.md` — elevated patterns.

Every page ends with an `evidence:` YAML block listing the source artifact paths + versions.

### Step 2 — Backlinks index

Write `design/WIKI/.backlinks.json` — reverse index of every `[[wikilink]]` and stable ID across the corpus. Regenerated by `node design/scripts/sync-wiki.js` on source version bumps.

### Step 3 — Report

Summarize: pages generated per category, total backlinks, any entity encountered without sufficient evidence (flag to Phase B as a gap).

## Phase B — Ongoing query (every session)

### Step 0 — Read the wiki index

Open `design/WIKI/index.md` to understand what's indexed. If the wiki doesn't exist, offer Phase A first.

### Step 1 — Classify the question

Determine the query axis:

- persona | principle | business rule | pattern | constraint | decision | screen | cross-cutting

### Step 2 — Retrieve

Pull the relevant wiki page(s) and source artifact(s). Never answer from the wiki alone — always cite the source artifact path + version.

### Step 3 — Synthesize

Write a cited answer. Use `[[wikilink]]` for entity references, `file.md:L42` for source citations. If the corpus doesn't cover the question, say so — don't fabricate. Suggest which upstream mode would produce the missing evidence.

### Step 4 — File back (with designer confirmation)

Classify any insight surfaced during the query:

- **Gap** → proposed AC bullet on the relevant canvas brief (ask before writing).
- **Contradiction between artifacts** → entry in `design/LINT_REPORT.md` queue.
- **Undocumented decision** → proposed entry in `design/DECISION_LOG.md` (show draft, ask to append).
- **Novel pattern** → flag for `design-governance` Phase B (write to `design/12_GOVERNANCE/_pattern-candidates.md`).

NEVER modify artifacts without explicit designer confirmation.

## Rules

- Every claim cites a source artifact with version.
- Wiki is synthesis, not authority — the artifact is ground truth.
- File-backs require designer confirmation.
- Retired artifacts remain cite-able but are excluded from orphan checks (`status: retired` frontmatter).
- After any source artifact version bumps, run `node design/scripts/sync-wiki.js` to refresh backlinks and flag stale pages.
